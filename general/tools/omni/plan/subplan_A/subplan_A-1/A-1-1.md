# A-1-1 — Import, login, list, status, remove, cooldown

Step 1 of A-1 ([`../A-1.md`](../A-1.md)). Status: **pending**.

## Commands this step implements (called from the CLI of A-5-2)

- `omni accounts import-default`: registers `@claude:default`, `@agy:default`, `@codex:default` as references to
  `$HOME/.claude`, `$HOME/.gemini` and `$HOME/.codex`, for each of them that exists. Nothing is copied and nothing in
  those directories is changed.
- `omni accounts login <claude|agy|codex> <profile> [--with-api-key] [--device-auth]`:
  1. creates `${OMNI_HOME}/profiles/<provider>/<profile>` (`0700`);
  2. links shared non-secret assets into it (`skills`, `themes`, `CLAUDE.md`, `AGENTS.md`) when they exist, never
     `auth.json`, credentials, sessions or sockets;
  3. for a Claude profile writes `"cleanupPeriodDays": 3650` into its `settings.json`;
  4. runs that CLI's own login with an isolated environment: `CLAUDE_CONFIG_DIR` (claude), `CODEX_HOME` (codex,
     `codex login`, with `--with-api-key` or `--device-auth` passed through), and for agy an isolated `HOME` whose
     `.gemini` is inside the profile directory (`agy acp --login`).
  The exact login subcommand of each CLI is read from its `--help` on the host at execution time and recorded in the
  report; if one of them has none, the executor stops and reports.
- `omni accounts list [--json]` and `omni accounts status [--json]`: `@<provider>:<profile>`, whether credentials
  appear to be present (file existence only, content never read), default model and effort, and
  `[COOLDOWN until HH:MM]` while `cooldown_until` is in the future.
- `omni accounts remove <@handle>`: deletes an isolated profile directory and its record. On any `@*:default` handle it
  refuses and exits 2; it never deletes `$HOME/.claude`, `$HOME/.codex` or `$HOME/.gemini`.

## Functions

`import_defaults(vault)`, `prepare_isolated_profile(vault, provider, profile) -> ProfileSpec`,
`child_env(spec, base_env) -> dict` (the environment a child CLI is started with), `login_profile(...)`,
`record_rate_limit(vault, handle, error_text)`, `remove_profile(vault, handle)`.

`record_rate_limit` recognizes an HTTP 429 and the text `try again at HH:MM` (as Codex prints it), turns the clock time
into the next such local time as an ISO string in `cooldown_until`, and stores nothing else from the error text.
