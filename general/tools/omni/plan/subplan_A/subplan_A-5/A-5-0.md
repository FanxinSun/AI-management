# A-5-0 — Parallel compare and four-section synthesis

Step 0 of A-5 ([`../A-5.md`](../A-5.md)). Status: **pending**. File: `omni/compare.py`.

## `run_compare(vault, store, handles, prompt, thread_id, turn_seq, with_prev, mode)`

- Finds the user turn to repeat (`turn_seq`, default the newest user turn), builds one packet per handle with
  `build_prompt_packet` (A-4-1), runs the adapters concurrently with `asyncio.TaskGroup`, and stores each answer as an
  assistant turn of `kind='compare'` under that user turn, `quoted_turn_id` set to the user turn.
- Output order is the order of `handles`, whatever the finishing order; a failing handle gives an `error` turn and does
  not cancel the others. A rate-limit error calls `record_rate_limit` (A-1-1).
- The answer text is the concatenated `text` events; `thinking` the concatenated `thinking` events; `tools_json` the
  tool events as a JSON list; `duration_ms` and `tokens_json` come from the timing and `meta`.

## `run_summarize(vault, store, thread_id, turn_seq, judge_handle)`

- Collects the user prompt and all assistant answers to it, and asks the judge (`--judge`, else the stored
  `judge_handle`, else the active handle) for exactly four Markdown sections in this order: `## Consensus`,
  `## Key Differences`, `## Unique Insights`, `## Verdict`.
- The reply is checked for the four headings in order; if one is missing the call is repeated once with the missing
  headings named, and a second failure ends with exit 1 and the raw reply kept in an `error` turn.
- The result is stored as a turn of `kind='synthesis'` whose parent is the prompt's user turn.

Tests use a fake adapter (no network), and one test checks the heading validation with a reply that lacks `## Verdict`.
